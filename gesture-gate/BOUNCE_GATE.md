# iOS bounce scroll physics gate

This is an additive gate for the iOS bounce scroll model. It does not edit
shared CI files, IR, the native ABI, or renderer sources.

The gate turns the bounce model into a machine-readable verdict so a change in
the physics cannot silently alter the overscroll behaviour.

Flutter 3.50.0 source anchors (`ab2912035e160d9cad6306df307576da6128ebdb`):

- `packages/flutter/lib/src/widgets/scroll_simulation.dart:18-132`:
  `BouncingScrollSimulation`; `:50-57` the iOS friction coefficient,
  `:59-72` the friction to spring handover, `:79-81` the velocity transfer
  cap.
- `packages/flutter/lib/src/physics/friction_simulation.dart:35-165`: the
  friction closed form, `finalX` and `timeAtX`.
- `packages/flutter/lib/src/widgets/scroll_physics.dart:748-946`: the rubber
  band spring, its 70 ms half life and the deceleration rate.

## Report

`gesture-bounce-report.json` is written by `tests/gesture_bounce_report.rs`:

```json
{
  "schema": "opurom.gesture.bounce/1",
  "source": "flutter-3.50.0:ab2912035e160d9cad6306df307576da6128ebdb",
  "clock": "logical",
  "metrics": {
    "bounce_friction_ppm": 135000,
    "bounce_transfer_cap": 5000,
    "rubber_band_half_life_ms": 70,
    "rubber_band_lambda_micro": 9902103,
    "rubber_band_decay_ppm": 500005,
    "bounce_overshoot_px": 122,
    "bounce_settle_steps": 33,
    "bounce_handover_steps": 53
  }
}
```

- `bounce_friction_ppm`: the iOS drag coefficient in parts per million.
- `bounce_transfer_cap`: the maximum velocity handed to the spring phase.
- `rubber_band_half_life_ms` and `rubber_band_lambda_micro`: the rubber band
  decay constant.
- `rubber_band_decay_ppm`: the displacement ratio after one half life; it
  must be one half.
- `bounce_overshoot_px`: the peak stretch the capped transfer can produce.
- `bounce_settle_steps`: frames needed for the rubber band to settle.
- `bounce_handover_steps`: milliseconds the friction phase runs before the
  spring takes over.

All values are logical counts or scaled constants, never wall-clock timings.

## Gate rules

1. The report is generated by the Rust fixture, or supplied with `--report`.
2. The four Flutter constants must match exactly. The derived counts are
   bounded, so a different libm rounding cannot fail the gate.
3. Without a baseline the verdict is `N/A` (exit `0`): the absolute limits
   were checked, but no regression comparison is possible.
4. With a baseline, the derived counts may not exceed `baseline * 2 + 8`; the
   exact constants must stay equal.
5. `PASS` exits `0`, `FAIL` exits `1`, usage or IO errors exit `2`.
6. The verdict is printed as `opurom.gesture.bounce.gate/1` JSON.

```sh
# Fresh report, absolute limits only.
node gesture-gate/gesture-bounce-gate.mjs

# Freeze a baseline and compare against it.
node gesture-gate/gesture-bounce-gate.mjs --write-baseline bounce-baseline.json
node gesture-gate/gesture-bounce-gate.mjs --baseline bounce-baseline.json

# Self tests: PASS, N/A and FAIL.
node gesture-gate/gesture-bounce-gate.mjs --self-test pass
node gesture-gate/gesture-bounce-gate.mjs --self-test na
node gesture-gate/gesture-bounce-gate.mjs --self-test fail
```

The joint gate runs this gate as its third evidence source and reports
`bounce_gate_status` and `bounce_machine_report`; the evidence archiver
stores the canonical bounce metrics as `bounce.json`.
